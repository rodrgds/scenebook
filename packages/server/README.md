# `@scenebook/server`

Self-hosted Scenebook control-plane and collaboration service components.

## Install

```sh
npm install @scenebook/server
```

The package exports the main server API, `@scenebook/server/migrate`, and test-support utilities from `@scenebook/server/testing`. It is ESM-only and requires Node.js 22 or newer.

The control plane includes independently signed and revocable per-user Sessions, hashed scoped API tokens, live Workspace RBAC, authenticated review attribution, immutable evidence and Releases, private-portal User/link grants, expiring signed share links, aggregate analytics, durable external-runner schedules, and an included first-party Console at `/console`. Scheduled Jobs contain no URL or executable command: an explicitly authorized external Runner leases an immutable repository/ref/Environment/Run-Target contract and may complete it only against the server-assigned Build evidence. It also includes a provider-neutral custom-domain lifecycle: strict hostname and DNS ownership proof, one live domain per Channel, explicit certificate/ingress reconciliation, disable/removal, and append-only audit. Custom-domain ingress remains fail-closed unless an external provisioner is configured; DNS proof alone never marks a domain active. The Console exchanges a personal API token for a short-lived browser Session, then provides tenant-scoped Scene/evidence browsing, visual Baseline comparisons, multi-reviewer assignment, region comments with attributed resolve/reopen actions, Channel history and rollback, private-share creation, schedule/Job/Runner coordination, custom-domain lifecycle management, analytics, membership/token controls, and audit history. One-time credentials are removed from the document after a short copy window. Content-addressed evidence pixels are served only after Project authorization and object-store integrity verification.

Public form submissions are bound to the current immutable Release and the selected stable CTA ID.
For canonical `step.ctas`, `ctaId` is required and only that CTA's webhook and typed field contract
are accepted; a deprecated single `step.cta` remains compatible through a deterministic fallback
ID. Accepted CTA identity and fields are encrypted at rest, while the non-secret identity is also
stored on the submission record for durable attribution.

An optional operator-configured GitHub App adds a deliberately narrow source-change and Check plane. Workspace Owners bind an installation to an exact `owner/repository` only after live verification. Authored Scene-tree edits are restricted by parsed scalar span and AST path, with schema validation, production MDX compilation, and TypeScript parsing; assets remain immutable. Source changes use Git compare-and-swap plus PostgreSQL-clock renewable leases whose latency-aware watchdog aborts unsafe remote writes. Check Runs are keyed by exact commit, immutable Build ID/hash, and Review identity, serialized across replicas with a bounded advisory lock, and reconciled through exhaustive bounded pagination; terminal state cannot regress silently. The customer-owned Action remains the executor, while App keys stay in runtime configuration and short-lived installation tokens stay only in memory.

Final evidence retention is opt-in and reference-aware. It uses a Workspace-scoped claim/revalidate/delete/tombstone lifecycle, separate grace periods for ordinary evidence and short-lived traces/videos, bounded batches, dry runs, and an append-only tenant audit trail. Scene assets and State screenshots, approved Baselines and their source Runs, approved Run reviews, every immutable Release ledger, and Release-upload bytes are protected regardless of age. Scene creation, Run approval, and retention use the same Workspace lock and active-object check. Expired `claimed` and fail-closed `deleting` rows are reconciled idempotently; the final tombstone, required retention event, and tenant audit commit atomically after physical deletion, scheduled failures are contained, and shutdown aborts and awaits an active pass. Physical deletion is unavailable unless a separate `FinalObjectDeleter` capability is configured; S3 deployments must supply a different delete-only credential from both the ordinary control-plane key and publication-gateway key.

`GET /v1/admin/workspaces/:workspaceId/export` streams a bounded portable ZIP using client-pull backpressure and cancellation propagation. `manifest.json` hashes `workspace.json`, `restoration.json`, and every included object. The restoration graph covers Scene assets and State screenshots, Run states/attachments/traces, Baselines, Release outputs, and Release archive/inventory/compiler-manifest objects; a corrupt or missing required object rejects the export. Only explicit immutable-record privacy policy can exclude a referenced object; every exact missing reference is recorded and makes `restorable` false. The metadata includes full Scene revision history, review discussions/assignments/decisions, evidence records, Channels/Releases/Baselines, schedules and Jobs, non-secret GitHub installation bindings, portal metadata, artifact inventory, and audit references. It omits App keys and installation tokens, API/session/share/Runner credentials, token hashes, webhook/CTA secrets, raw analytics identifiers, encrypted payloads, storage keys, DNS ownership values, and provisioner operation credentials. Record count, asset count, asset bytes, serialized metadata bytes, and exact total ZIP bytes fail the whole export before streaming rather than silently truncating it.

`SCENEBOOK_ADMIN_TOKEN` is an operator-only bootstrap fallback; browsers and CI must use personal credentials or GitHub OIDC respectively. Human Sessions and private shares are Ed25519-signed by the control-plane-only active private key; control plane and publication gateway verify the active public key plus at most three bounded rollover public keys selected strictly by `kid`. The gateway receives public keys only, while the independent identity-token secret is retained only for opaque personal API-token HMACs. `SCENEBOOK_PUBLICATION_URL` is mandatory and must be a different origin from `SCENEBOOK_PUBLIC_URL`. Newly issued private links point to that origin with the one-time share credential only in the URL fragment. Authenticated Users use a separately generated, one-use publication-login handoff bound to their live source Session, exact User Portal grant, publication audience, and return path; the control plane stores only its digest and never puts the control-plane Session in the publication URL. Handoff consumption and its audit event commit atomically, so an audit-store failure leaves the credential retryable. The control plane's legacy `/portal/private` route is only a fragment-preserving redirect shell: it does not resolve or serve active publication content. The separate `@scenebook/gateway` service owns hosted publication delivery. See `deploy/SELF_HOSTING.md` in the project repository for the route contract and operational guidance.

## Corresponding source

This AGPL package includes its complete `src/` TypeScript directory, `migrations/` SQL directory, and self-contained `tsconfig.json`/`tsconfig.build.json` build configuration alongside the compiled `dist/` output. `package.json#source` identifies `src/index.ts` as the source entry point. These are the preferred forms for modifying this package. After installing its development dependencies, `bun run build` rebuilds `dist/` with TypeScript 7.

Deployers who modify and run this package as a network service are responsible for the source-availability and notice obligations in the AGPL.
